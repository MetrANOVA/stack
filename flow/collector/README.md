# Flow collectors (nfacctd, sfacctd)

This directory contains flow collectors using the [pmacct](https://github.com/pmacct/pmacct) components for IPFIX (nfacctd) and sFlow (sfacctd). Each collector has a `conf.example/` template folder that must be copied to `conf/` before the container can start.

## Quick start

```bash
cp -r flow/collector/nfacctd/conf.example flow/collector/nfacctd/conf
cp -r flow/collector/sfacctd/conf.example flow/collector/sfacctd/conf
```

Each `conf/` directory must include a `kafka/` subdirectory with:
- `kafka.env` (exported credentials from the Kafka init step)
- `ca.crt` (Kafka CA certificate)

The build script (`docker/build.py`) will copy these from the message bus export directory into `conf/kafka/` for you. If you do it manually, place them here:
- `flow/collector/nfacctd/conf/kafka/kafka.env`
- `flow/collector/nfacctd/conf/kafka/ca.crt`
- `flow/collector/sfacctd/conf/kafka/kafka.env`
- `flow/collector/sfacctd/conf/kafka/ca.crt`

## Configuration

Each collector renders its config from Jinja templates and `.env` files:

- Collector env file: `conf/nfacctd.env` or `conf/sfacctd.env`
- Kafka env file: `conf/kafka/kafka.env`
- Templates: `conf/templates/*.j2`
- Shared templates: `../shared/templates/*.j2`

The init containers render templates into `conf/` at startup. To force overwriting existing files, set `FORCE_UPDATE=true` in the collector env file.

You can customize behavior in two ways:

1. Edit the `.env` files
   - Example keys: `KAFKA_BROKER`, `KAFKA_TOPIC`, `COLLECTOR_ID`, `FORCE_UPDATE`
2. Edit the templates directly
   - Collector templates: `conf/templates/*.j2`
   - Shared templates: `../shared/templates/*.j2`

## Environment variables

Collector env files (`conf/nfacctd.env`, `conf/sfacctd.env`) support:

- `KAFKA_BROKER`: Kafka bootstrap (default: `kafka:9093`)
- `KAFKA_TOPIC`: Kafka topic (default: `metranova_flow` for nfacctd, `metranova_sflow` for sfacctd)
- `COLLECTOR_ID`: Identifier used in logs/labels (default: `metranova_nfacctd_collector` or `metranova_sfacctd_collector`)
- `FORCE_UPDATE`: Set to `true` to overwrite existing rendered configs

Kafka env file (`conf/kafka/kafka.env`) is generated by the Kafka init step and provides at least:

- `KAFKA_COLLECTOR_PASSWORD`

## Shared components

`flow/collector/shared/` contains:
- `scripts/render_configs.py` used by both collectors
- Shared templates like `kafka.csv.j2` and `pretag.map.j2`

Each collector mounts the shared templates and uses the same render script with a collector name argument.

## Init containers

Both collectors include an init service in their compose files:
- `nfacctd-init`
- `sfacctd-init`

These run the shared render script to generate:
- `nfacctd.conf` or `sfacctd.conf`
- `kafka.csv`
- `pretag.map`

The main collector service depends on its init service completing successfully.

## Example compose usage

```bash
docker compose -f flow/collector/nfacctd/docker-compose.yml up -d
docker compose -f flow/collector/sfacctd/docker-compose.yml up -d
```

## Test data generators

Send IPFIX test data to nfacctd:

```bash
python3 flow/collector/nfacctd/scripts/send_ipfix.py --count 1000 --interval 0
```

Override destination host/port if needed:

```bash
python3 flow/collector/nfacctd/scripts/send_ipfix.py --host localhost --port 9996 --count 100
```

Send sFlow test data to sfacctd:

```bash
python3 flow/collector/sfacctd/scripts/send_sflow.py --count 1000 --interval 0
```

Override destination host/port if needed:

```bash
python3 flow/collector/sfacctd/scripts/send_sflow.py --host localhost --port 9997 --count 100
```

## Notes

- Both collectors send to Kafka using the `kafka.csv` config file.
- Auto topic creation is disabled in Kafka. Ensure topics exist before sending data.
